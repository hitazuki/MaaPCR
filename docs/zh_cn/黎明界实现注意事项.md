# 黎明界实现注意事项

本文记录黎明界自动化开发中已经踩过的共性问题，供后续 agent 调整 pipeline、模板和调试流程时参考。当前状态转移设计见 `黎明界自动化流程设计.md`。

## 状态机原则

### 全局分流只处理稳定页面

`黎明界_全局状态分流` 用于识别已经稳定停留的页面，可以包含 `黎明界_地图循环`。

不要让刚点击后的过渡状态直接回到全局分流。游戏经常在点击后仍停留旧画面数秒，但点击已经生效。如果此时回全局，旧地图页面会再次命中 `黎明界_地图循环`，导致重复选择节点。

### 点击后进入特化等待

会触发页面跳转的点击动作应优先进入当前节点链路的特化等待，不要直接回 `黎明界_全局状态分流`。

当前常用等待节点：

- `黎明界_角色节点移动后目标等待`
- `黎明界_EX节点移动后目标等待`
- `黎明界_NORMAL节点移动后目标等待`
- `黎明界_EVENT节点移动后目标等待`
- `黎明界_RELIC节点移动后目标等待`
- `黎明界_SHOP节点移动后目标等待`
- `黎明界_BOSS节点移动后目标等待`
- `黎明界_角色特写后角色加入关闭`
- `黎明界_战斗预览后目标等待`

特化等待只放本链路可能出现的稳定目标页和必要确认，超时后再回退 `黎明界_全局状态分流`。不要在特化等待里放 `黎明界_地图循环` 或地图节点选择。

旧的 `黎明界_过渡目标等待` 和 `黎明界_页面关闭后目标等待` 已删除。后续不要重新引入宽泛通用等待；开始链路、地图节点链路和结束链路应分别维护自己的明确后继。

### 弹窗优先于底层页面

确认弹窗出现时，底层页面的标题和按钮仍可能可见并被模板命中。例如商店退出确认弹窗背后仍能识别到商店标题或关闭按钮。

因此弹窗确认节点必须排在对应底层页面处理节点之前。商店相关顺序应保持：

```text
商店离开确认 -> 商店处理
```

商店离开确认应优先使用 OK 按钮模板匹配，不要依赖 OCR；OCR 漏识别时会导致 `商店处理` 点击弹窗外区域，等同于取消确认。

### 地图节点选择

地图节点点击后统一走：

```text
地图选择XXX -> XXX节点移动确认OK -> XXX节点移动后目标等待 -> XXX固定链路
```

如果没有弹出移动确认，`XXX节点移动确认OK` 超时后也应进入本节点的目标等待，而不是立即回全局。

### 角色特写

以下动作可能触发全屏角色特写：

- 初始角色确认
- 角色奖励选择
- 事件获取角色
- 结果页继续后弹出的角色获取特写

这些动作后应进入角色特写点击循环。每次点击后只尝试识别 `character_join_title.png`，也就是角色加入页面标题；识别不到就继续点击，识别到后关闭角色加入页并进入各自后继。

不要把一个共享的“角色特写后稳定目标”作为小全路由挂在特写链中。共享稳定目标超时会把“特写还没点掉”误判为任务失败，也会重新引入正常链路反复跑宽路由的问题。

角色特写点击坐标应尽量放在中上方，例如 `[640, 240]`，避开地图节点、底部按钮和弹窗确认按钮。不要默认点击屏幕中心或底部区域。

### 战斗流程

编队点击 `战斗开始` 后进入本链路的战斗结果等待，不要回全局。`黎明界_通用战斗结果等待` 只作为异常兜底链路使用。战斗加载和自动战斗过程可能会短暂命中编队页或其他旧页面，回全局容易重复编队。

## 模板策略

### 固定分辨率

当前模板基于 1280x720 识别。所有截图和视频帧裁剪都应保持 720p 原始比例，不要拉伸或缩放。

### 截图来源要求

用于制作模板的截图应避免：

- 确认弹窗
- 点击光圈或闪光
- 横幅提示和 toast
- 加载遮罩
- 过场模糊
- 节点贴边
- 角色、怪物或 UI 遮挡目标主体

如果只能从视频取帧，优先挑点击前或动画稳定后的清晰帧。

### 地图节点模板

地图节点必须按类型和状态分别建模板：

- NORMAL
- EXTREME
- SHOP
- EVENT
- 遗物（蓝色立方体）
- 角色（粉红公主像）
- BOSS

每类都区分高亮可点击态和非高亮反例态。只有高亮态能进入点击节点，非高亮模板只用于参考和避免误用。

NORMAL、EXTREME、BOSS 等敌人节点不建议裁完整怪物立绘。不同敌人或 Boss 立绘差异较大，应优先裁底座文字和奖励图标。SHOP、EVENT、遗物、角色节点也应尽量裁稳定图标和必要高亮边，不要带大块背景。

地图节点模板不要裁得过低。节点靠近屏幕底部时，底座下沿可能被左下资源图标、撤退/归还按钮或其他 UI 遮挡。遗物、EVENT、SHOP、角色等节点优先裁上半部核心图标和必要高亮边，少裁底座底部。

### OCR 使用

OCR 在本地调试和不同插件环境下可能不稳定。能用模板匹配的按钮、标题、节点类型优先用模板。OCR 仅作为临时方案或文本变化较大的兜底。

## Windows 编码注意

PowerShell 管道内的 inline Python 可能会把中文字符串转成 `???`，尤其是脚本中硬编码中文节点名并写回 JSON 时。处理中文节点名时优先：

- 用 `apply_patch` 做小范围编辑；
- 用 Python 读取现有 UTF-8 文件并按已有键名操作；
- 用 Unicode 转义字符串表示中文节点名。

修改后检查是否出现乱码键：

```powershell
@'
import json
from pathlib import Path
data = {}
for path in Path("assets/resource/pipeline").glob("limingjie*.json"):
    data.update(json.loads(path.read_text(encoding="utf-8")))
print([key for key in data if "?" in key])
'@ | python -
```

## 调试与校验

每次修改 `assets/resource/pipeline/limingjie*.json` 后至少运行：

```powershell
Get-ChildItem assets\resource\pipeline\limingjie*.json | ForEach-Object { python -m json.tool $_.FullName > $null }
git diff --check
```

复杂路由修改后检查 duplicate route：

```powershell
@'
import json
import re
from pathlib import Path
data = {}
duplicate_nodes = []
for path in sorted(Path("assets/resource/pipeline").glob("limingjie*.json")):
    part = json.loads(path.read_text(encoding="utf-8"))
    for name, node in part.items():
        if name in data:
            duplicate_nodes.append((name, str(path)))
        data[name] = node
issues = []
missing = []
for name, node in data.items():
    seen = []
    for field in ("next", "on_error"):
        value = node.get(field) if isinstance(node, dict) else None
        if isinstance(value, list):
            for route in value:
                if route in seen:
                    issues.append((name, route))
                seen.append(route)
    for field in ("next", "on_error", "all_of", "any_of"):
        value = node.get(field) if isinstance(node, dict) else None
        if isinstance(value, list):
            for route in value:
                if isinstance(route, str):
                    target = re.sub(r"^(\[[^\]]+\])+", "", route)
                    if target not in data:
                        missing.append((name, field, route, target))
print("duplicate_nodes", duplicate_nodes)
print("duplicate_routes", issues)
print("missing", missing)
'@ | python -
```
